<interfaces>
OnlyOffice callback status contract：1=editing connection state，2=ready for save/close，4=closed without changes，6=force-save；只有 storage 接受结果时返回 JSON `{"error":0}`。

Durable session 固定字段：`doc_key`, `repo_id`, `normalized_path`, `username`, `operation_id`, `generation`, `expected_file_id`, `expected_commit_id`, `state`, timestamps。

Durable callback key 由 signed payload 中 `key/status/url` 的规范化值计算；outcome states 固定为 `processing|committed|conflict|failed`，重复 delivery 返回既有 outcome。
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| deployment env → Hub/worker/Document Server | 同一 secret 必须安全注入，缺失不能降级。 |
| Document Server callback → Hub | body/header JWT、status、doc key 与 content URL 均是不可信输入。 |
| Hub callback → Server mutation/release | 异步重试可能陈旧或并发，必须 durable claim 与 generation fence。 |

## STRIDE Threat Register

| Threat ID | Category | Severity | Component | Disposition | Mitigation Plan |
|---|---|---:|---|---|---|
| T-01-20 | Spoofing | critical | OnlyOffice callback JWT | mitigate | enabled startup 强制非空同源 secret；HS256 verify 在任何 side effect 前；critical 未关闭即阻断。 |
| T-01-21 | Replay | high | duplicate/concurrent callback | mitigate | SQL unique claim、prior outcome、restart/concurrency E2E。 |
| T-01-22 | Tampering | high | async save/release | mitigate | doc session绑定 generation/file/commit；fenced update与 exact release。 |
| T-01-23 | Information Disclosure | high | secret/error/log/UI | mitigate | 不记录 secret/token/generation；sanitized FileViewTip；Compose test 不输出实值。 |
| T-01-24 | Server-Side Request Forgery | high | callback content URL | mitigate | signed payload后仍限制 scheme/Document Server origin、timeout与size bound。 |
| T-01-25 | Denial of Service | medium | callback/download retry | mitigate | atomic processing claim、bounded timeout/size、失败可重试但不并发重复写。 |
</threat_model>
