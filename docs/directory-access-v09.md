# v0.9 目录资格裁决契约

状态：目录 API 和原生文件读写已接通，完整真实登录及发布验收仍待完成。旧 ACL ABI 保持兼容，统一共享链路要求 scoped ABI 2。

目录共享与访问权限统一存入 cf_dir_acl：同一库、路径、类型、主体只有一行。share_mode=1 提供无库访问资格，实际 r/rw/none/invisible 和继承由该 ACL 及现有优先级裁决；share_mode=0 的 ACL 不提供无库资格。新界面默认开启共享，旧 API 省略字段保留既有模式（新建为 0）。库根与文件规则不得开启共享。共享资格必须验证 lifecycle_ref，目录删除重建不能继承旧共享。硬只读、账户状态与撤权屏障不变。

ACL 与目录管理权两表使用原生 seafile 数据库和 Hub 版本化迁移，不由 EAP 或 Django 建表；升级、结构校验与发布命令见 [目录表结构升级](directory-schema-upgrade.md)。

资格只覆盖目标路径。调用方提供完整且当前有效的祖先 ACL 与已校验资源生命周期的共享记录；纯核心匹配主体和路径但不验证数据库、会话、资源身份或签发传输凭据。祖先无资格不等于祖先 invisible；后者继续阻止子目录直达。多个不相交目录的资格不能合并成父目录资格。

会话与签发凭据不属于纯核心，由 Hub 身份层和 Server 原生条件复核承担。原生 OIDC 与 Authentik
旧 OAuth 浏览器会话都映射到同一个 `Profile.login_id` 业务主体，并各自携带 Server 可复核的会话
证明（`oidc_session` 或 `browser_session`）；两种认证的库/目录权限结论必须一致。细节见
[目录管理与地址接口](directory-access-v09-http.md)「多认证会话证明」。

新纯核心使用独立 cf_acl_evaluate_scoped 符号与 scoped ABI 版本，保持旧 Context/Rule/Result 布局和 cf_acl_evaluate 行为。库资格存在时保留原权限基线；无库资格时必须存在已验证的共享模式 ACL，实际权限按 ACL 裁决，不存在独立共享的隐式 r 回退。非法输入、缺失上下文、停用与屏障均拒绝。

共享记录不提供管理权或转授权能力。共享/ACL 管理、批量枚举、资源改名删除、字节读取和写入事务必须各自完成真实授权接线；调用纯核心成功不能替代这些工作。

跨语言用例见 [目录资格用例](directory-access-v09-cases.json)，Server C 与 Hub ctypes 适配测试消费同一份数据。上线仍须通过部署与真实身份端到端验收。

### 系统管理员的库内容资格

修改原因：后台 `can_manage_library` 是管理能力，不能把日常管理员自动提升为全库内容读写者。仅当前有效、`is_staff=1` 且角色为 `system_admin` 的原生账号获得全库 `rw` 基线；已有 `can_manage_library=false` 覆盖仍关闭该资格。没有 AdminRole 行的原生管理员沿用 CE 的 `system_admin` 默认值；显式 `default_admin`、`daily_admin`、未知或空角色均不提供隐式内容资格。普通库管理员保留原个人/群组管理标记和内容访问授权，日常管理员后台管理能力不变。

该基线在 Hub 当前事务、Server 原生权限和 Branch 最终写入检查使用相同语义，不能绕过目录 ACL、硬只读、停用和撤权屏障，不写入每库授权或新增配置。共享角色用例见 [系统管理员资格用例](system-admin-content-cases.json)。

## 2026-10-13 第二批实现（历史记录，共享模型已由统一 ACL 替代）

Hub 已接入目录管理授权、共享管理、共享目录分页和地址解析 HTTP 路由；接口契约见 [目录管理与地址接口](directory-access-v09-http.md)。部署工厂复用可信原生生命周期 reader；新增 041 目录管理授权分页索引。分级授权严格限制向下再委派，管理资格和内容资格分开裁决；共享命令增加事务内幂等记录与强版本删除。共享发现固定请求主体 epoch，逐目录复核当前资格和生命周期，过滤拒绝项仍推进分页。

现有目录权限页改接新 ACL 接口并增加共享配置，支持条件编辑/删除、稳定请求重试及分页。共享不提供独立读写选择，也不维护 ACL；目录管理授权仍仅 API。部门/角色使用提供方的限定标识，管理员输入命名空间以避免跨目录歧义。

本批通过 Hub 真实 SQL/C、HTTP/服务/宿主回归；前端 7 项测试、定向 ESLint 和 ACL 生产 bundle 编译通过。未完成 Server 原生资格装载与最终读写、真实会话/下载凭据联验、以太客消费页联调和发布升级验收。v0.9 仍为开发中，不能把当前接口成功视为原生文件读写已开放。

## 统一 ACL（2026-10-14）

共享列表是 share_mode=1 的 ACL 投影，不再使用独立共享表。兼容 shares 创建接口在不存在 ACL 时创建 r/继承/共享 ACL；已有 ACL 时只开启共享，保留 permission 和 inherit；重复调用不旋转 revision。兼容删除接口只关闭共享并旋转同一 ACL revision，保留库用户 ACL；删除 ACL 则同时撤销共享。共享接口和 ACL 接口共用 ID 与 ETag，旧 ETag 不能覆盖另一入口的修改。

同路径多主体继续采用既有 user/dept/group 优先级；共享资格不绕过 none/invisible。关闭某行共享不撤销其他主体或祖先授予的有效共享。旧 shares 不包含权限的响应不再是独立资源，调用方应刷新 ACL/共享列表。

离线升级保留历史迁移校验和；旧共享只存在时转换成 r/继承 ACL，重合时保留 ACL 权限/继承并开启共享。已有 ACL 的 ID 保留、revision 更新；只存在共享时保留共享 ID。冲突或损坏记录阻止迁移，不猜测身份。转换成功后直接 DROP cf_dir_share，不归档、不恢复独立共享表；运行时仅访问 cf_dir_acl。
