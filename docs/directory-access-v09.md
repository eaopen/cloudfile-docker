# v0.9 目录资格裁决契约

状态：开发中，未声明 HTTP/文件传输入口已接通。旧 ACL ABI 保持调用兼容；v0.9 新链路采用本契约，不设置存量规则审查门槛。

cf_dir_share 是独立资格事实，默认只读、覆盖非根目录及子树，不存 permission、不增删 cf_dir_acl。有效目录正向 ACL 可独立提供访问资格，遵守 inherit。库根 ACL 不产生无库资格的整库入口。默认资格进入同一 ACL 裁决，rw 可提升，none/invisible 按现有主体与继承优先级限制；硬只读与身份/撤权屏障不变。

资格只覆盖目标路径。调用方提供完整且当前有效的祖先 ACL 与已校验资源生命周期的共享记录；纯核心匹配主体和路径但不验证数据库、会话、资源身份或签发传输凭据。祖先无资格不等于祖先 invisible；后者继续阻止子目录直达。多个不相交目录的资格不能合并成父目录资格。

新纯核心使用独立 cf_acl_evaluate_scoped 符号与 scoped ABI 版本，保持旧 Context/Rule/Result 布局和 cf_acl_evaluate 行为。库资格存在时保留原权限基线，无库资格时共享提供 r 基线，否则由有效目录正向规则建立资格。非法输入、缺失上下文、停用与屏障均拒绝。

共享记录不提供管理权或转授权能力。共享/ACL 管理、批量枚举、资源改名删除、字节读取和写入事务必须各自完成真实授权接线；调用纯核心成功不能替代这些工作。

跨语言用例见 [目录资格用例](directory-access-v09-cases.json)，Server C 与 Hub ctypes 适配测试消费同一份数据。共享持久化与读取链路未接通前不启用生产入口。

## 2026-10-13 第二批实现

Hub 已接入目录管理授权、共享管理、共享目录分页和地址解析 HTTP 路由；接口契约见 [目录管理与地址接口](directory-access-v09-http.md)。部署工厂复用可信原生生命周期 reader；新增 041 目录管理授权分页索引。分级授权严格限制向下再委派，管理资格和内容资格分开裁决；共享命令增加事务内幂等记录与强版本删除。共享发现固定请求主体 epoch，逐目录复核当前资格和生命周期，过滤拒绝项仍推进分页。

现有目录权限页改接新 ACL 接口并增加共享配置，支持条件编辑/删除、稳定请求重试及分页。共享不提供独立读写选择，也不维护 ACL；目录管理授权仍仅 API。部门/角色使用提供方的限定标识，管理员输入命名空间以避免跨目录歧义。

本批通过 Hub 真实 SQL/C、HTTP/服务/宿主回归；前端 7 项测试、定向 ESLint 和 ACL 生产 bundle 编译通过。未完成 Server 原生资格装载与最终读写、真实会话/下载凭据联验、以太客消费页联调和发布升级验收。v0.9 仍为开发中，不能把当前接口成功视为原生文件读写已开放。
