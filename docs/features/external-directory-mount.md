# CloudFile 外部资料联邦模块（External Content Federation）

> 用途：定义外部内容联邦模块的项目边界、双消费者架构与分阶段验收路线
> 适用版本：Seafile CE 14 参考基线
> 当前状态：规划；当前仓库无该模块的实现、配置或测试证据

## 定位与项目边界

外部资料联邦模块负责以统一、受控的接口访问仍由外部系统保存的文件与目录。它应先作为
独立项目开发和验证，拥有自己的发布、配置、凭据、日志、测试与故障边界；CloudFile 只是
其消费者之一。接口稳定并完成两个目标消费者的验收后，再评估将它泛化为可供更多产品
复用的内容联邦平台，不能在首个 MVP 中预设所有存储、协议和写入语义。

OpenList 和 rclone 属于该模块内部的外部存储适配器或运行组件，而不是要求消费者自行
编排的旁路服务。模块负责固定兼容版本、封装差异、转换错误并约束超时与重试；协议实现、
远端存储能力和组件自身漏洞响应仍归各上游项目负责。

## 两类消费者

| 消费者 | 需要的能力 | 明确边界 |
|---|---|---|
| AI 应用的统一文件知识库接口 | 按授权列举目录、读取文件与范围、取得稳定资源标识和元数据、接收变更游标，并为解析、切分、索引或检索提供内容入口 | 模块不内置模型、向量库、问答编排或业务知识权限；索引副本不得绕过源端与联邦策略 |
| CloudFile 虚拟目录挂载 | 将已授权的联邦目录显示为独立入口，提供浏览、单文件读取、故障状态和审计关联 | 不把外部文件伪装为 Seafile 原生对象，也不自动获得桌面同步、WebDAV、历史、锁或回收站语义 |

两个消费者必须使用同一套规范化资源模型、授权终判和审计上下文；不得各自直连 OpenList
或 rclone，否则适配器差异、权限和故障语义会重新泄漏到产品层。

## 与现有概念的区别

### Seafile 虚拟资料库

Seafile virtual repo 是同一 Seafile 对象模型中某个资料库子目录的逻辑视图，数据仍由
commit、FS object 和 block 表达。外部资料联邦中的资源由外部系统保存，其资源标识、
版本和目录入口都不能作为 Seafile 对象存在的证明。

### 当前 SMB/NFS `local-path` 外部资料源

当前 [SMB/NFS 外部资料源](external-sources.md)要求运维先在宿主机完成 SMB/NFS 挂载，
再以只读 bind mount 暴露给容器；CloudFile 中已存在 `local-path` provider、授权、浏览与
下载等实现证据。外部资料联邦模块则是尚未实现的独立服务，通过内部 OpenList/rclone
适配器访问外部系统。两者可面向相似数据，但部署边界、凭据持有方、接口和实现状态不同，
不能互相推断能力完成情况。

## 规划中的 MVP 架构

```text
AI 应用                         CloudFile
  │ 统一文件知识库接口             │ 虚拟目录挂载接口
  └──────────────┬────────────────┘
                 ▼
          外部资料联邦 API
   资源模型 · 身份/策略 · 审计 · 变更游标
                 │
        适配器契约与运行时隔离
          ┌──────┴──────┐
          ▼             ▼
   OpenList 适配器   rclone 适配器
          └──────┬──────┘
                 ▼
       外部文件系统 / 对象存储
```

MVP 以只读联邦为边界，至少包含以下组件与契约：

- **联邦 API**：提供源登记、目录列举、资源详情、单文件/范围读取、变更游标和健康状态；
  对路径、分页、排序、错误码、取消和幂等请求给出版本化契约。
- **规范化资源模型**：使用模块内稳定 ID 表达源、目录与文件；记录外部 ID、路径、大小、
  修改时间、内容类型、版本/ETag 和能力标记，但不合成 Seafile commit 或 block ID。
- **身份与策略层**：将消费者身份映射到联邦主体、源和路径权限；每次列举、读取和变更
  获取都在服务端终判，默认拒绝，不能以界面隐藏代替授权。
- **适配器层**：OpenList/rclone 实现同一契约，负责协议差异、路径编码、分页、范围读取、
  取消、限流和错误转换；适配器进程或连接池故障不能拖垮其他源。
- **凭据与审计**：按源使用最小权限凭据，凭据不下发给消费者；日志关联消费者、联邦请求、
  适配器与外部操作，同时避免记录密钥和文件内容。
- **变更与内容入口**：为 AI 消费者提供可恢复的扫描游标和删除标记；MVP 不承诺实时事件，
  内容缓存仅在定义容量、过期、加密、权限失效和清理责任后启用。

## MVP 统一语义

| 主题 | MVP 约束 |
|---|---|
| 可用模式 | 只读列举、详情和文件读取；读写、同步和双向变更传播不属于 MVP |
| 权限 | 源端权限与联邦策略取更严格结果；策略或身份映射不可用时拒绝访问 |
| 版本 | 仅透传可验证的外部版本/ETag；没有版本能力时明确标记未知，不展示为 Seafile 历史 |
| 一致性 | 允许外部存储最终一致，但必须暴露资源已变化、游标失效和部分读取失败 |
| 故障 | 超时、拒绝访问、限流、凭据失效和源不可达使用不同错误；不可达不能显示为空目录 |
| 隔离 | 单一源或适配器失败只影响对应资源；不得进入 Seafile 同步权限的网络终判路径 |
| 搜索 | MVP 提供 AI 索引所需的内容与变更接口，不承诺内置全文或向量检索 |

## 分阶段实施与验收

### 阶段 0：独立项目与契约基线

- 建立独立仓库、版本策略、威胁模型和可本地复现的开发环境。
- 固定联邦 API、资源模型、适配器契约和错误分类；提供不依赖 CloudFile 的契约测试夹具。
- 用一个受控外部源验证路径规范化、分页、范围读取、取消、超时和路径逃逸防护。

验收：独立进程可通过版本化 API 完成只读列举和读取；非法路径、失效凭据与外部超时均
产生可区分且默认拒绝的结果。

### 阶段 1：OpenList/rclone 适配器与联邦核心

- 将 OpenList 和 rclone 作为模块内适配器接入，统一能力发现、健康检查和错误转换。
- 完成按源凭据隔离、身份/路径策略、审计关联、变更游标和删除传播。
- 增加单元测试、适配器契约测试、容器端到端测试与断网、限流、进程退出等故障注入。

验收：同一套测试对两个适配器通过；一个源或适配器故障不影响其他源；日志可追踪请求且
不泄露凭据；重启后扫描游标可恢复或明确要求安全重扫。

### 阶段 2：AI 统一文件知识库接口

- 发布面向 AI 应用的消费者 SDK/API，支持增量发现、授权读取、范围读取和资源版本校验。
- 验证解析/索引流水线只能处理调用主体可读资源，权限撤销和删除能够传播到索引消费者。

验收：用参考 AI 索引消费者完成首次扫描、增量更新、删除、权限撤销和内容版本变化测试；
索引失败不阻塞联邦浏览，联邦授权失败不会退化为使用旧内容。

### 阶段 3：CloudFile 虚拟目录挂载

- 通过联邦 API 增加独立入口、身份映射、只读浏览、单文件读取、健康状态和审计引用。
- 保持原生资料库和当前 `local-path` 外部资料源的路由、数据与故障隔离。

验收：容器端到端覆盖授权与越权、深层目录、大文件范围读取、源不可达、凭据轮换和两个
消费者并发访问；界面不会把联邦资源声明为原生资料库，也不会暴露未实现的历史、锁、
同步或 WebDAV 能力。完成阶段 0 至 3 后，才可把 MVP 状态改为“验证中”。

## MVP 后持续改进

MVP 验收后按独立能力逐项设计和发布：性能基线与配额、加密内容缓存、事件驱动增量、更多
适配器、可观测性与升级回滚、跨区域与高可用，以及读写直通或单向/双向同步。读写需要先
定义原子性、冲突、锁、重命名、删除传播和失败恢复；任一能力完成都不能自动代表其他模式
已经可用。每次扩展必须同时更新契约、威胁模型、兼容矩阵和端到端验收。

在上述代码、配置和测试证据出现前，架构图、组件选型或路线图均不能作为已实现证明。
