## 本次实际补充

Go 最终锁查询之前的结构识别收紧为完整 15 列 path 布局或完整 16 列 resource 布局，与 Hub 的完整集合校验一致。拒绝之前可被五个字段子集误识别的残缺表，也拒绝夹杂另一布局字段的表；增加相关回归测试。已有锁、未知结构或 SQL 错误继续拒绝写入，不创建 Checkout 会话。

SQL 门禁的边界须明确：当前校验 CREATE 与 Hub 读取合同，并固定 45 份 SQL/迁移文件摘要，能阻止这些输入未经审查变化；它不自动证明全部 C/Go/Python 读写 SQL 与运行数据库兼容，也不覆盖所有 bootstrap 内联 DDL。迁移测试和完整启动测试不能由摘要门禁代替。

## 后续实施顺序与验收条件

1. **上传修复交付**：固定 Server/Hub/Docker/EAP 提交及构建收据，核对运行镜像，部署后以普通 API 上传并下载回读；不调用 Checkout/Checkin。出现不兼容结构直接失败，检查日志不再十次重试。完整构建及 DEV 部署仍等待明确授权。
2. **确定唯一 Schema 管理入口**：先登记每张表的实际消费者、初始化器、升级器和当前数据；把 bootstrap 的所有扩展 DDL 纳入清单。新安装只有一个明确 DDL 入口；已有卷启动只做契约验证，升级另行显式执行。修改启动入口前必须补齐它目前创建的被依赖表，不能简单删调用。
3. **完成读写契约统一**：同时处理 Go 最终提交、已编译 cf-lock.c、cloudfile-policy.c、Hub 编辑/组目录/ACL、存储绑定读写与冷读/GC。核心表校验应包含类型、长度、字符集/排序规则、NULL/默认值、索引唯一性/列顺序/前缀、引擎及生命周期语义。明确未选目标布局的支持期限，避免无期限双契约。
4. **离线迁移设计**：迁移前重新只读统计有效、过期、挂起 Guard 和 Intent/Session，检查孤立 resource、generation、凭据 epoch、基础版本及路径关联；盘点两张存储绑定表的键冲突、悬空库和对应对象路径。先形成每类记录保留/转换/拒绝迁移规则，再安排停止全部写入者、备份及恢复演练。DDL 非事务，不可承诺自动回滚；保留不可改写的历史校验和和可恢复的逐步执行记录。数据转换、环境变量和回滚另行明确审批。
5. **验收矩阵**：新安装、已有当前布局、已识别的历史布局、残缺/混合布局、迁移中断重启分别测试。普通文件覆盖 0B/1B/1KB/64KB/1MB、中文/空格名、同名覆盖与保留编号、子目录、直传和 EAP 中转；每例检查目录实际名称、大小、下载哈希。批量中途失败不得整批假成功，说明之前成功的文件不自动回滚。锁定文件拒绝越权覆盖、同库无锁文件可写，下载无需 Checkout；并发取得锁与 Branch 提交不能绕过终判。

EXDEV 另做隔离 Linux 挂载测试，覆盖后端目录、库目录和分片目录 bind mount；确认失败不会发布半文件、重试不会制造错误完成回执。当前 macOS 定向测试不能代替这些 Linux 用例。部署验收保留镜像 Digest、提交 SHA、时间、状态码及字节哈希，日志不包含账号凭据或上传票据 URL。
